## 1. Design decisions

### D1 — The selection rule is a layer in front of the gate

`extract_candidates` → `select(candidate)` → `admit(selected, metric=..., ...)`.
Selection decides *worth* (section, attribution, metric); the gate decides
*grounding* (span, notation, study-parameter, parseability). The gate is
untouched: `TestTheGateIsNotTheSelectionRule` (test_admit.py:913-952) and the AST
sole-constructor test must keep passing. Selection never constructs a `Claim`.

### D2 — `SelectionRejection` with a closed selection-side cause vocabulary

New frozen record in `selection.py`, same shape as `NonClaim`
(`cause: str, text: str, location: Location`) but its causes come from a new
closed frozenset `SELECTION_CAUSES`, **distinct from** the gate's
`NON_CLAIM_CAUSES` (PRD M4). Rationale: gate causes describe grounding/notation
failures; selection causes describe worth failures — C5 wants to tell them apart.
No shared base with `Claim` or `NonClaim`.

Causes (closed, one per category — the tests assert the cause):

| Cause | Category (acceptance) | Deterministic rule this slice |
|---|---|---|
| `reference_numeral` | reference-list numerals, citation markers | `section_hint == references`, or context is a bracketed citation `[n]`, `[a,b]`, `(a,b)` in a citation position |
| `outside_sections` | criterion (c) | `section_hint == other` (no abstract/results/table); `references` is `reference_numeral` |
| `year` | publication/citation years | candidate is a 4-digit integer (no decimal, no thousands separator) in [1900, 2100] **and** a date cue in the immediate context (`in`, `between`, `from`, `since`, `during`, `(`, `–`, `, 20`) — conservative; a count like "enrolled 2020" without a cue is not rejected |
| `figure_number` | page/figure/table/equation numbers | context contains `fig`, `figure`, `table`, `page`, `pp`, `eq`, `equation`, `suppl`, `supplementary` |
| `version_string` | version strings | candidate text is ≥2 dot-separated numeric groups, or context contains `version`, `v1`-style, `release` |
| `doi_digits` | grant/DOI/ORCID digits | context contains `doi`, `orcid`, `grant`, or a `10.`+`/` pattern |
| `hyperparameter` | hyperparameters | context contains `learning rate`, `batch size`, `epoch`, `dropout`, `kernel size`, `window size`, `hidden unit`, `seed`, `lr =` (closed list, conservative) |
| `axis_label` | axis labels | context contains `axis`, `x-axis`, `y-axis`, `tick`, `scale` |
| `related_work` | another paper's result (R4) | context contains `et al`, `reported`, `found`, `showed`, `observed`, `previous`, `prior work`, `study by`, or a `(Surname, 20XX)`-style attribution |
| `no_named_metric` | criterion (b) — also closes the N fall-through (M5) | `metric_of` yields empty after noise stripping |

**Check order is the contract** (mirrors `admit.py`'s "ORDER IS THE CONTRACT"):
1. `references` → `reference_numeral`; `other` → `outside_sections`
2. lexical context categories in the table's order (`year`, `figure_number`,
   `version_string`, `doi_digits`, `hyperparameter`, `axis_label`,
   `reference_numeral`, `related_work`)
3. metric naming → empty ⇒ `no_named_metric`
4. pass: `Selected(candidate, metric, units)`

Order affects cause attribution only (never the score) — but it must be stable
and documented. The N fall-through class (`n of 412`, `| n | 412 |`) dies at
step 3: `n` supplies no metric. The gate's `study_parameter` refusal and
`study_parameters(raw)` are not re-implemented by the rule.

### D3 — The metric namer: free-text quantity phrase, deterministic

`metric_of(candidate) -> str | None`:
1. Take the text **before** the value within the sentence: between the previous
   boundary (sentence start, `;`, `:`, `,`, `(`, `[`) and the candidate's start.
2. Strip trailing function words/operators from a closed list: `is`, `was`,
   `were`, `are`, `of`, `for`, `in`, `by`, `with`, `at`, `=`, `<`, `>`, `≤`, `≥`,
   `:`, `,`, `±`, `(`, `[`, `the`, `a`, `an`.
3. Strip leading determiners/pronouns: `the`, `a`, `an`, `we`, `our`, `their`.
4. Collapse whitespace. Empty ⇒ `None`.

Examples: `The sensitivity was 0.87` → `sensitivity`; `AUC of 0.92` → `AUC`;
`95% CI: 0.4%-1.7%` → `95% CI`; `p < 0.001` → `p`; `prevalence estimate of 4.3%`
→ `prevalence estimate`. For table cells, if the `Candidate` record exposes a
column header (the agent checks `candidates.py` first), prefer
`column_header`; else the cell's own preceding text. Provisional by design —
unit-tested on hand-built contexts; the blind labels do not score metric text.

### D4 — Units: best-effort pass-through, no `value.py` changes

Units are read from the token immediately after the candidate within its context,
from a closed small list (`%`, `kg`, `g`, `mg`, `μg`, `ml`, `mL`, `mm`, `cm`,
`ms`, `s`, `Hz`, `IU`, `ng`, `nM`, `µM`) — passed as `units=` to `admit`.
`parse_value` is **not** changed: a candidate whose text itself carries a
non-`%` unit still yields `unparsed_value` (a known recall gap that surfaces in
the blind score, `extraction-core/spec.md:170-173`). Never guess a unit.

### D5 — Scoring: pooled + per-paper, floor on first sight

`scoring.py` is rule-agnostic: `score(labels, predict) -> Score` where `predict:
Callable[[Candidate], bool]`. `Score` = counts (TP/FP/FN/TN) + precision/recall,
with `None` for undefined (no positives predicted / no positive labels). Pooled
score over all 73 rows is the headline number; per-paper breakdown reported too.
A floor test (`test_blind_score_floor.py`) asserts pooled precision ≥ FLOOR and
recall ≥ FLOOR, with `BLIND_SCORE_FLOOR` a named module constant whose value is
set when the score is first seen (owner decision, PRD M6). A first score below
the agreed floor forces rule revision before merge — the slice can fail.

### D6 — `extract_claims` is the engine seam

`pipeline.py`: `extract_claims(raw: str) -> tuple[tuple[Claim, ...],
tuple[NonClaim | SelectionRejection, ...]]`. Normalizes once (the same
`normalize_text` the spans index), runs candidates → selection → gate. Does not
re-implement `study_parameters` (document-level N extraction stays in `admit`).

## 2. Phases

### Phase 0 — Blind labels (owner-blocked, first commit)

- **Goal:** the ordering deliverable. Owner fills 73 rows across the five
  `fixtures/labels/*.todo.jsonl` files (claim / not-claim, nothing else).
- **Files:** `fixtures/labels/*.todo.jsonl` (filled).
- **Validation:** `load_labels` round-trips without `LabellingError`
  (via `uv run pytest tests/extract/test_labelling.py` and a quick load check);
  `git diff` shows only `"label": null` → `"label": "..."` changes.
- **Commit (integrator):** `Fill the blind labels for claim selection` — the
  first commit on the branch.
- **Blocks:** every later phase.

### Phase 1 — Scoring harness (TDD, rule-independent)

- **Goal:** precision/recall computed and reported, before the rule exists.
- **Files:** `src/plumb/extract/scoring.py`, `tests/extract/test_scoring.py`.
- **Rules:** `score(labels, predict) -> Score`; counts + precision/recall;
  `None` for undefined; deterministic ordering (labels keep file order — no
  sorting needed, but never iterate a `set`); no `float()` — count first, then
  `Decimal` division.
- **Tests first:** synthetic `LabelledCandidate` fixtures; mixed predictions;
  all-negative predictions (precision `None`); all-not-claim labels (recall
  `None`); empty labels error.
- **Commit:** `Add precision/recall scoring for the blind label set`

### Phase 2 — Selection rule (TDD, the core)

- **Goal:** `selection.py`: `SELECTION_CAUSES`, `SelectionRejection`, `Selected`,
  `select(candidate)`, `metric_of(candidate)`, units token.
- **Files:** `src/plumb/extract/selection.py`,
  `tests/extract/test_selection.py`.
- **Tests first** (each category one failing-first test asserting **not a claim**
  with its cause): publication year; figure number; version string; DOI digit
  sequence; reference-list numeral (references section + `[30,31]` citation);
  hyperparameter; axis label; related-work sentence (`et al`, `(Smith, 2019)`);
  `outside_sections` for `other`; `no_named_metric` for `n of 412` and a table
  cell `| n | 412 |` (M5 — assert via the metric test, no per-spelling rules);
  metric namer positive cases (D3 examples); units pass-through (`0.87` with
  `kg` in context_after); check-order stability (a candidate matching two causes
  yields the documented one); `TestTheGateIsNotTheSelectionRule` still green.
- **Determinism:** only `Candidate` fields are read; closed frozensets for
  membership; fixed check order; no `hash()`/`set` iteration; no timestamps.
- **Commit:** `Add the claim-selection rule with named causes`

### Phase 3 — End-to-end wiring (TDD)

- **Goal:** `pipeline.py`: `extract_claims(raw)` — the seam C4 consumes.
- **Files:** `src/plumb/extract/pipeline.py`, exports in `__init__.py`,
  `tests/extract/test_pipeline.py`.
- **Tests first:** a small hand-built paper runs end-to-end (claims + rejections
  correct); the five fixture papers run deterministically (byte-identical across
  two calls); every claim's span round-trips and `metric` is non-empty; every
  rejection carries a `SELECTION_CAUSES`/gate cause; N appears in claims exactly
  never; the AST sole-constructor test still passes.
- **Commit:** `Wire claims end to end through selection and the gate`

### Phase 4 — Blind scoring + floor (TDD)

- **Goal:** the slice's headline output: pooled precision/recall over the 73
  real rows, floored.
- **Files:** `tests/extract/test_blind_score.py` (or extend `test_scoring.py`),
  `BLIND_SCORE_FLOOR` constant.
- **Tests first:** a test that loads each paper's candidates + filled labels,
  predicts via the pipeline, computes pooled + per-paper scores, and asserts
  pooled precision ≥ FLOOR and recall ≥ FLOOR. The score is printed/recorded in
  the test output; the PR states the score, the floor, and the ordering.
- **Integrator checkpoint:** show the owner the score; agree the floor; set the
  constant; if below floor, return to Phase 2 for revision (the slice fails
  honestly rather than merging a low score).
- **Commit:** `Report and floor the blind selection score`

## 5. Testing strategy

`uv run pytest` per phase (keep the suite green after each commit). The repo-wide
AST guard (test_determinism.py) auto-covers new modules: no `float(`, no bare
`hash(`/`id(`, no unallowlisted imports. Every phase's tests are written before
its code. The floor test is the only test whose value depends on human input —
it is written in Phase 4, after the labels exist, and its constant is set at
first sight.

## 6. Edge cases & error handling

- Undefined precision/recall (no predicted positives, no positive labels) →
  `None`, reported as such, never `0.0` silently.
- A candidate matching multiple rejection categories → the documented check
  order decides the cause (stable, tested).
- `load_labels` refuses missing/unlabelled/edited rows → the Phase 4 test uses
  the real files; a `LabellingError` there means the label commit is incomplete.
- Candidates whose metric is empty in a table cell → `no_named_metric` (column
  header absent and cell text has no quantity phrase).
- **No verdict vocabulary anywhere**: causes are spelled unlike verdicts; the
  slice emits no `REPRODUCED`/`DIVERGED`/`UNVERIFIED`.
