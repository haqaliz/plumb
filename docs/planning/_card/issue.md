## Selection rule (fixed BEFORE selection — the screening doctrine)

`docs/planning/gate-paper/survey.md:6-14` criteria, with criterion 4 retargeted to what the
spine now captures:

1. Paper openly licensed (CC BY preferred) so it can be a fixture.
2. Public code, pure Python, runs on a laptop CPU in minutes, **no network at run time**.
3. Data bundled or generated by the code; nothing gated.
4. **Headline numbers computed in a notebook cell** (root `.ipynb` entry or fallback): the
   value appears in a cell `stream` or `execute_result` `text/plain` output, not only in
   committed CSVs.
5. Deterministic or seeded, so the value can be `REPRODUCED` within the paper's written
   precision (the `Point`/`Bound` comparison; `float_repr` where the artifact writes
   shortest-repr floats).
6. A buildable environment: modern-Python `uv`-compatible, or an earliest-buildable recorded
   drift boundary (Perrin precedent, `fixtures/gate/perrin/README.md`).

Plus the gate-paper anti-inflation guard (P2): claims are rule-encoded (every numeric cell of
the relevant table/§, all of them — including any that turn out not to bind), each
`reported_value.text` occurring **verbatim** at its span in the normalized paper text.

## Fixture template (Perrin/AgroDesign precedent)

Provenance README with SHA-256 pins; a spec generator (rule-encoded claims + bindings,
exactly-once `unique_offset` spans); a dev-time run via `tools/` (real env build, freeze,
`drift.json` M4a cross-check if the environment drifts); committed record
(`fixtures/gate/<slug>/`); offline tests (fixture grounding, byte-identical replay, C1
recovery floor, no-local-path scan, CLI `--from-record`); bank with owner-reviewed labels on
every `DIVERGED`. The dev-time env build and real run happen only via `tools/`, never in
tests or CI.

## Acceptance tests, written first (offline)

1. The committed record replays through the CLI byte-identical (`--from-record --json`
   equals the record's `verdicts.json`).
2. At least one claim's verdict is produced through a `notebook_cell` locator, the located
   value read only by hash from a fresh cell artifact; a committed/stale notebook is
   `STALE_ARTIFACT`, never read (constraint #5).
3. C1 conformance floor on the new paper: the fixed rule's claims are grounded verbatim
   (anti-inflation); C1's automatic recovery is reported as conformance, not coverage.
4. `plumb verify --bank` folds the case; `corpus report` pools it with denominators and the
   owner-authority marker; every `DIVERGED` labeled by the owner.
5. No local paths in committed evidence; byte-identical across invocations
   (PYTHONHASHSEED-varied); full suite green and network-free.

## Caveats

- The panel search may find nothing qualifying — the honest outcome is a documented miss
  (the ReScience catalogue failed 13/13; the first panel found 1/4). The unit's fallback:
  record the miss with evidence rather than force a paper.
- Real kernels are allowed at dev time for the fixture's own run (nbconvert executes the
  checkout's notebook) — never in tests/CI.
- Runtime budget: laptop-CPU minutes; if the candidate's headline run exceeds ~20 minutes,
  it fails criterion 2 (the claims rule may still cover a bounded subset — PRD decision).
