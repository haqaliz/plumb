## Implementation steps

1. **Failing test first**: `test_cli_core.py` with acceptance tests 1–6 from the spec.
2. Build `src/plumb/cli.py`:
   - `build_parser()` — argparse with subcommand `verify`; paper/repo positional; flags
     `--rev`, `--bindings`, `--out`, `--from-record`, `--no-env-build`, `--signer-key`,
     `--no-paper`, `--json`. Help text documents flags, exit codes, bindings contract.
   - `main(argv=None) -> int` — parse (argparse errors → exit 2), dispatch to
     `cmd_verify(args)`; wrap dispatch in try/except mapping every engine exception to a
     named cause via `_map_cause(exc) -> tuple[str, str]`; print
     `plumb verify: <CAUSE>: <detail>` to stderr; return 1. Catch-all → `SPINE_ERROR`.
   - Dispatch table: `cmd_verify` in this aspect routes to the not-yet-built render/replay/
     live-spine functions via importable seams (`render_verdicts`, `replay_record`,
     `run_live` — to be provided by later aspects). For this aspect, the *failure* paths
     (usage, causes) are fully wired; the success paths call the seams which later aspects
     implement. **Do not** raise "not implemented" for the success path in a way that
     tracebacks — map to `SPINE_ERROR` (it will be replaced next aspect).
   - `_map_cause` handles: `SourceNotFound`, `RevNotFound`, `UnsupportedArchive`,
     `EnvBuildFailed`, `EntryPointMissing`, `EntryPointAmbiguous`, `BindingInvalid`,
     `PdfInputError`, `BundleRefused`, plus `ValueError` from `parse_trace`/`parse_claims`
     (→ `RECORD_INVALID`) and the run cause records (`WONT_RUN`/`TIMEOUT`/`NO_ARTIFACT`/
     `STALE_ARTIFACT` — these flow through verdicts, not exceptions, but the mapping must
     exist for the run-level-cause path).
3. Refactor: keep the mapping table data-driven (cause → tuple), keep `main` thin.

## Edge cases

- argparse's own error messages go to stderr and exit 2 — assert that shape, don't re-wrap
  usage errors in the named-cause vocabulary (usage = exit 2, distinct from exit 1 causes).
- `main()` must never raise: every path returns an int. A test asserts
  `main([...]) == code` for each trigger and that stdout is empty on failure paths.
- `--json`/`--out` accepted but inert in this aspect only in the sense that the seams are
  stubs — the flags must parse without error now (render/replay/live-spine tests rely on it).
