# render — implementation plan (2026-09-27)

Execute test-first (RED → GREEN → REFACTOR). One agent owns this aspect.

## Setup

- Worktree as in cli-core. Depends on cli-core's dispatcher seam contract (a function that
  takes a `VerdictSet` and returns bytes — `render_verdicts(verdict_set, *, json: bool) ->
  bytes`).
- No new dependency. Tests live in `tests/cli/test_render.py` (+ a determinism test file).

## Files to create/modify

- `src/plumb/cli/render.py` — `render_verdicts(verdict_set, *, json: bool) -> bytes` and
  `_render_json`, `_render_table`, `_render_summary`.
- `src/plumb/cli/__init__.py` (or wire into `cli.py`) — the seam callable by the shell.
- `tests/cli/test_render.py` — schema, table golden, degenerate sets.
- `tests/cli/test_render_determinism.py` — cross-process byte-identity (subprocess with

- Golden fixture: `tests/cli/golden/table_agrodesign.txt` (committed; generated from the
  replayed AgroDesign record, reviewed byte-by-byte before committing).

## Implementation steps

1. **Failing test first**: `test_render.py` — `--json` schema (fields equal to
   `serialize_verdicts` per-claim records + `run_id` + `coverage`), canonical JSON byte rules
   (sort_keys, separators, one trailing newline, no NaN — reuse the engine's serialization
   convention, `src/plumb/extract/serialize.py:81-129`), table golden byte-match, degenerate
   sets (zero claims, all-UNVERIFIED), truncation at 24 chars documented and tested.
2. Build `render.py`:
   - `_render_json`: build the object from `VerdictSet` (verdicts sorted by claim_id already,
     `verdict.py:116-140`; `coverage` via the property; per-claim fields from the `Verdict`
     record — reuse the same field names/text rendering as `serialize_verdicts`, including
     Decimal-as-text: inspect `src/plumb/verify/serialize.py:40-47` and mirror it, or reuse
     it if it exposes a per-claim record builder).
   - `_render_table`: fixed columns `VERDICT | CAUSE | CLAIM ID | REPORTED | REDERIVED |
     ARTIFACT | LOCATOR`, fixed widths, truncation at 24 chars with `…`, separator line,
     summary block (per-verdict-kind totals in fixed order REPRODUCED, WITHIN-TOLERANCE,
     DIVERGED, UNVERIFIED; `bound`/`claims`; `by_cause` alphabetical). No volatile data.
   - Empty set: `VERDICT | ...` header + `0 claims` summary line; `--json` → empty
     `verdicts` array.
3. Determinism tests: subprocess two invocations, `PYTHONHASHSEED=0` vs `PYTHONHASHSEED=1`,
   identical bytes for both formats.

## Edge cases

- Decimals: rederived/delta/band values must render as exact text, never float
  (the engine refuses float coercion — mirror it; `allow_nan=False`).
- Truncation must not split a multi-byte character.
- `located_text` can contain newlines (CSV cells) — table cell rendering must sanitize
  (replace newlines with `␤` or space) and the JSON must keep them verbatim.
