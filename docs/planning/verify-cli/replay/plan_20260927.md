## Implementation steps

1. **Failing test first**: `test_replay.py` acceptance 1 — `--from-record
   fixtures/gate/agrodesign/ --json` exits 0, stdout byte-identical to the committed
   `verdicts.json`-derived golden (86 claims; 85 REPRODUCED / 1 DIVERGED). Build the golden
   from the committed record itself (the re-derivation must equal `serialize_verdicts` of
   the committed verdicts — the existing replay test's assertion shape, adapted to CLI
   output).
2. Build `replay.py`:
   - Read members: `claims.json` → `parse_claims` (records) → `readmit(records,
     normalized_text=...)` — note: readmit needs the paper text; the record may not carry
     the paper. Check `fixtures/gate/agrodesign/` for the paper (paper.pdf exists). If the
     record lacks the paper, re-admission cannot run — **decide in the dig**: either the
     record must contain the paper (it does for the gate record), or replay uses
     `parse_claims` records directly with a `readmit`-equivalent path. The honest rule: the
     admission gate is the only door to `Claim` (`admit.py:346-354`), so replay must have
     the paper (record dir paper, or `--paper` arg? — spec says no paper arg; the record's
     paper.pdf is used; a record without paper → `RECORD_INVALID` naming the missing paper,
     unless the record is a raw extraction record — flag this in the dig before coding).
   - `parse_trace(trace_bytes)` → `RunTrace` (id mismatch → ValueError → `RECORD_INVALID`).
   - `Capture(store=record.objects, artifacts=trace.artifacts, stale=trace.stale,
     causes=trace.causes)`.
   - `load_bindings(bindings_bytes, claim_ids)` → `BindingInvalid` → `BINDING_INVALID`.
   - `verify_claims(claims, bindings, Completed(trace, capture))` → `VerdictSet`.
   - Cross-check: if record has `verdicts.json`, `serialize_verdicts(re-derived) ==
     record verdicts.json`; mismatch → `RECORD_INVALID` (detail: "re-derivation differs").
   - Output via `render.render_verdicts`; exit 0 iff all claims decided (PRD contract).
   - `--out`: `build_bundle(...)` with signer from `~/.ssh/plumb_bundle_ed25519` /
     `--signer-key` (missing key → `KEY_MISSING`), paper from record dir (include by
     default; `--no-paper` omits), bindings bytes, trace, capture, environment.txt text,
     source — derive `SourceRecord` from the trace/record (dig: what does the trace carry?
     `trace.py:50-66` has tree_hash/argv — check if source is serialized; if not, replay
     records source as the record's own `source` or a `replayed` marker; `build_bundle`
     requires a `SourceRecord`, so the dig must find what the record carries).
   - `verify_bundle(out_dir, allowed_signers=..., principal="plumb-bundle")` after build —
     the built bundle must verify; refusal → `BUNDLE_REFUSED`.
3. Failure paths (spec acceptance 3–4): tampered trace id, missing members → `RECORD_INVALID`
   via the CLI's `_map_cause` (ValueError → RECORD_INVALID).
4. Refactor: keep `cmd_verify` dispatch table clean; replay owns record-format knowledge.

## Edge cases

- The `objects/` store in the record holds 21 files but the bundle only the bound outputs —
  `build_bundle` computes that itself from the capture; replay must pass the full capture.
- Record with `verdicts.json` absent: cross-check skipped, replay still succeeds (gate
  record has it; a raw record may not).
- `RECORD_INVALID` detail must name the member (missing `objects/`, missing `claims.json`,
  id mismatch, verdict mismatch).
- Exit 0 only when all 86 decided; any UNVERIFIED in a replayed record → exit 1 (test 7).
