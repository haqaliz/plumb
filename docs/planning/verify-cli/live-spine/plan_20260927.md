# live-spine — implementation plan (2026-09-27)

Source: `docs/planning/verify-cli/live-spine/spec.md`, PRD `docs/planning/verify-cli/prd.md`.
Execute test-first (RED → GREEN → REFACTOR). One agent owns this aspect. Depends on cli-core
+ render being merged; replays' signing/bundle test helpers are reused.

## Setup

- Worktree as before. Synthetic-repo test pattern: `tests/verify/test_verify_e2e.py:53-99`
  (resolve_local → stub env build → run_and_capture → verify_claims); stub env:
  `tests/verify/verify_helpers.py`. Fixture repo under `tests/cli/fixtures/` (a `main.py`
  writing a JSON artifact, plus a markdown paper + bindings).
- Tests live in `tests/cli/test_live_spine.py`. No network (conftest blocks sockets); the
  real env build is never constructed in tests.

## Implementation steps

1. **Failing test first**: `test_live_spine.py` acceptance 1 — synthetic repo + paper +
   bindings + `--no-env-build` → exit 0, table + `--json` correct, REPRODUCED where the
   artifact matches.
2. Build `live.py`:
   - Paper: read bytes; `.pdf` → `pdf_to_markdown` (`PdfInputError` → `PAPER_UNREADABLE`);
     `.md` → decode utf-8; `extract_claims(text)`; `hash_paper` for the bundle.
   - Repo: `resolve_local` / `resolve_git(url, rev)` / `resolve_archive` by input kind
     (kind detection: existing directory → local; `://` or `git@` → git; `.tar.gz`/`.tgz`/
     `.zip` → archive; else `PAPER_UNREADABLE`-style usage — actually `USAGE_ERROR`/exit 2
     for an unknown repo kind, named causes exit 1 for resolution failures).
   - Env: `describe_environment(checkout)`; if `no_env_build` → construct the offline stub
     EnvBuild (mirror `tests/verify/verify_helpers.py`); else `build_environment(checkout,
     descriptor, runner=uv_sync_runner)` (real build — dev-time, user-invoked).
   - Run dir: `workdir.py` derives `runs/verify-<tree-digest12>-<argv-hash8>` under a
     CLI-owned work root (deterministic from inputs; recorded in the trace).
   - Run: `resolve_entrypoint(checkout, manifests, explicit=None)` →
     `EntryPointMissing`/`EntryPointAmbiguous` (exit 1, named); `run_and_capture(checkout,
     env_build, entrypoint, run_dir=..., timeout_seconds=1800)` → `RunTrace`, `Capture`.
   - Bindings: `load_bindings(path.read_bytes(), claim_ids)` → `BindingInvalid` →
     `BINDING_INVALID` (exit 1).
   - Verdicts: `verify_claims(claims, bindings, Completed(trace, capture))`; on pre-run
     exceptions use `NoRun.from_exception` → all-`UNVERIFIED` VerdictSet (run-level cause
     governs; false-`DIVERGED` guard holds through the CLI).
   - `--out`: `build_bundle(...)` (signer key discovery: `--signer-key` or
     `~/.ssh/plumb_bundle_ed25519`, missing → `KEY_MISSING`; paper included by default,
     `--no-paper` omits) then `verify_bundle` on the result (refusal → `BUNDLE_REFUSED`).
   - Output via `render.render_verdicts`; exit per PRD contract.
3. Failure paths (acceptance 3–5): resolution failure, missing entry point (run-level
   cause in table, not an exception path — `NoRun.from_exception`), stub-env-only guarantee.
4. Determinism (acceptance 7): same-process double invocation byte-identical; the run dir
   must be deterministic (test asserts the same run dir name for two invocations on the
   same inputs — same tree hash → same dir; note: a second run reuses the previous run's
   outputs if files are newer than... the freshness guard's job; the test asserts the dir
   name, and that the trace records it).
5. Refactor: keep `cmd_verify` thin; live owns spine ordering.

## Edge cases

- Vacuous paper (zero claims): run still executes, empty table, exit 0 (acceptance 8).
- `--rev` given for a local dir: usage error (exit 2) — `--rev` only applies to git URLs.
- Bindings referencing claim ids that extraction didn't produce → `BindingInvalid`
  (orphan ids) → exit 1 — the CLI surfaces the cause, the user fixes the bindings.
- STALE_ARTIFACT: the freshness guard's output files predate the run → `UNVERIFIED` table,
  exit 1, bytes never read — no CLI-level special handling needed (engine enforces), but a
  test asserts the table shows the cause.
- Work root default: a CLI-owned dir under the user's cwd or `~/`? Decide: default
  `<cwd>/.plumb-runs/` unless `--run-dir` (not in this slice) — record in the dig; must be
  deterministic and documented in `--help`.
