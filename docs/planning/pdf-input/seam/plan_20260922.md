## Phases

### Phase S1: failing seam tests (RED)

- **Goal:** the acceptance tests, written first, defining the arithmetic so they cannot be
  gamed (seam spec "Open questions").
- **Prerequisites:** fixtures + frontend.
- **Files:**
  - `tests/extract/test_pdf_seam.py` — failing tests:
    - For each `fixtures/papers/PMC*.pdf` with a Markdown sibling:
      1. `extract_claims(pdf_to_markdown(pdf_bytes))` runs without error.
      2. **Abstract floor:** every claim the Markdown path finds whose section is the
        abstract is recovered by the PDF path by `Claim.id` (denominator: Markdown-path
        abstract claims; numerator: PDF-path claims matching by id).
      3. **Whole-paper floor:** claim-id recovery ≥ 0.90 (the floor from the survey; if the
        survey set a different floor, use that number — it is written into
        `fixtures/papers/README.md` and must be quoted in the test docstring).
      4. Recovery reporting: the test prints per-paper `(recovered, total, rate)` and a
        table-cell count for the PDF path (S1 accounting) — printed, not asserted, so the
        numbers are visible in CI output.
      5. **Span round-trip** on PDF-derived claims: `text[location.start:location.end] ==
        claim.reported_value.text` over the converted text (the
        `test_pipeline.py:66-76` pattern).
    - A fixture that cannot clear the floor is handled per PRD M4: the test asserts the
      README documents the exclusion with its measured rate (assert the README mentions the
      PMCID) rather than failing on recovery — exclusion is a recorded, labeled state.
    - Cross-process byte identity of the converted text on one fixture (subprocess pattern,
      `test_determinism.py:307-436`).
- **Validation:** `uv run pytest tests/extract/test_pdf_seam.py` fails (no converter seam
  yet / failures are the RED); the rest of the suite stays green.
- **Commit:** `Fail test: PDF claims equal Markdown claims by id at the recovery floor`

## Testing strategy

- The seam tests ARE the acceptance criteria — write them first, let them define the
  arithmetic (denominator/numerator pinned in the test docstrings).
- Full suite must stay green; the no-network and determinism suites are the guardrails.
- Report-only accounting (S1) keeps the numbers visible without gating on them; the floors
  are the gates.

## Environment & determinism

- `uv run pytest` from the worktree root; no env vars; no network (autouse blocker).
- Cross-process determinism of the PDF path is pinned in this aspect (criterion 1 of the
  PRD).

## Edge cases & error handling

- Fixture below floor → M4 exclusion path, documented with measured rate, asserted as
  documented — never a silent drop, never a hard fail on an honest conversion gap.
- Recovery arithmetic: denominator/numerator definitions are written into the test
  docstrings in S1 so no later edit can shift claims between buckets.
- If the seam itself needs changing to pass, that is a PRD violation: stop, flag, ask.

## Agent execution notes

- Task S1 and S2 can be the same agent (RED→GREEN on the same tests) or two agents with S1's
  failure output as the handoff; sequence S3 last (depends on S2's reality).
- Checkpoint for human review: after S2, show the per-paper recovery table from the test
  output — the gate's "honest number" for this slice.
- If a fixture lands below the floor, surface the survey-vs-reality gap in the checkpoint
  rather than quietly excluding (M4 documents it, the human sees it).
