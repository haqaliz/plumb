# Implementation plan — `pdf-input/fixtures` (2026-09-22)

Source: `docs/planning/pdf-input/prd.md` + `docs/planning/pdf-input/fixtures/spec.md`.

## Project setup checklist

- No `src/` changes. Work in the worktree root (repo already has `pyproject.toml`,
  `uv.lock`, and `tests/` — not greenfield for this aspect).
- Dev-time fetch tool under `tools/` — `tools/` already exists (`tools/label_blind.py`).
- Fixtures land in `fixtures/papers/` as `PMC*.pdf`.
- `.gitattributes` gains a `*.pdf` binary rule.

## Phases

### Phase F1: failing fixture test + binary plumbing (RED)

- **Goal:** a failing test asserting the five PDF fixtures exist, plus the git plumbing so
  binary files survive checkout.
- **Prerequisites:** none.
- **Files:**
  - `tests/extract/test_pdf_fixtures.py` — failing test: globs `fixtures/papers/PMC*.pdf`,
    asserts five files, each above a size floor (e.g. ≥ 10 KiB), matching the five known
    PMCIDs from `fixtures/papers/README.md:23-29`.
  - `.gitattributes` — append `*.pdf binary` (or `*.pdf -text`).
- **Validation:** `uv run pytest tests/extract/test_pdf_fixtures.py` fails (no PDFs yet);
  `git check-attr text -- fixtures/papers/PMC*.pdf` shows unset after the fetch.
- **Commit:** `Fail test: PDF fixtures must exist for the five CC BY papers`

### Phase F2: fetch the PDFs (GREEN)

- **Goal:** the five real journal PDFs on disk, sourced and recorded.
- **Prerequisites:** F1.
- **Files:**
  - `tools/fetch_pdf_fixtures.py` — dev-time script; for each PMCID in the README table,
    resolves the Europe PMC full-text PDF URL, downloads to `fixtures/papers/PMC<id>.pdf`,
    records source URL + fetch date; prints a manifest. Explicitly marked never-to-run-in-
    tests; no test imports it.
  - `fixtures/papers/PMC*.pdf` — the five binaries.
  - `fixtures/papers/README.md` — provenance update: PDF source URLs, fetch date, the DOI
    resolution (the `<!-- source -->` comment wins where the README table disagreed —
    PMC12780771, PMC13363872), any residual disagreement noted, plus the fetch tool usage.
- **Validation:** fixture test passes; `uv run pytest` still green (line-ending pin
  intact); `git status` shows the PDFs as binary.
- **Commit:** `Add real journal PDFs of the five CC BY papers, sourced from Europe PMC`

### Phase F3: signal survey (measure the floor)

- **Goal:** heading-recovery and table-recovery numbers on the first PDF, recorded before
  the frontend design is locked (PRD M3).
- **Prerequisites:** F2.
- **Files:**
  - `tools/pdf_signal_survey.py` — dev-time probe: uses pypdf (dev-only install acceptable
    here; the frontend aspect pins it as a runtime dep) to dump text per page, count
    `##`-recoverable headings vs the Markdown's headings, and count reconstructable table
    lines vs the Markdown's pipe tables, for one chosen paper (e.g. PMC13134363 — the
    largest abstract label set). Prints the two recovery rates.
  - `fixtures/papers/README.md` — append the survey numbers (heading rate, table rate,
    date, probe name).
- **Validation:** the README carries concrete numbers; the survey's heading/table recovery
  rates are recorded. If headings recover at or near 1.0 and tables above ~0.5, proceed
  with the ≥ 90% whole-paper floor; if the survey says otherwise, note the adjusted floor
  in the README and flag it in the seam plan (M4 exclusion path).
- **Commit:** `Record PDF signal survey: heading and table recovery on PMC13134363`

## File-by-file build order

1. `tests/extract/test_pdf_fixtures.py` (failing test)
2. `.gitattributes` (`*.pdf binary`)
3. `tools/fetch_pdf_fixtures.py`
4. `fixtures/papers/PMC*.pdf` (5 binaries)
5. `fixtures/papers/README.md` (provenance + survey)

## Testing strategy

- The aspect's tests are the fixture-existence test (F1) plus the existing suite staying
  green. The survey is a dev-time measurement, not a test (its numbers set the floor).
- Network: the fetch runs once at dev time; tests never touch the network (autouse
  blocker in `tests/conftest.py:56-60`).

## Environment & determinism

- No runtime dependency changes in this aspect. `uv` dev env may gain pypdf for the probe
  if convenient, but the frontend aspect owns the runtime pin.
- PDFs are content-addressed by git; determinism requirement: the fixture bytes must not be
  altered by checkout — the `.gitattributes` binary rule is the mechanism, verified by
  `git check-attr`.

## Edge cases & error handling

- Europe PMC endpoint changes: recorded URLs allow manual re-fetch; if a PDF is
  unobtainable, record it in the README and note the exclusion (PRD M4) — the fixture test
  is adjusted with a named cause, never a silent drop.
- DOI discrepancies: resolved by the `<!-- source -->` comment, residual disagreement
  noted in the README.

## Agent execution notes

- The fetch is an authorized, read-only network fetch at dev time (precedent
  `fixtures/papers/README.md:15-17`) — the same posture, documented.
- Checkpoint for human review: none needed unless a PDF cannot be fetched; in that case
  stop and ask.
- The survey's numbers are the handoff to the frontend agent — include them verbatim in
  the frontend task prompt.
