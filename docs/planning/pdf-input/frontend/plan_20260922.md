### Phase P2: the converter (GREEN)

- **Goal:** `pdf_to_markdown` implemented to spec.
- **Prerequisites:** P1.
- **Files:**
  - `src/plumb/pdf/__init__.py` — exports `pdf_to_markdown`.
  - `src/plumb/pdf/convert.py`:
    - `pdf_to_markdown(pdf_bytes: bytes) -> str` — opens via pypdf's `PdfReader` from
      bytes (never from a path/URL), walks pages, extracts text with pypdf's visitor API to
      capture font size per text run.
    - Heading reconstruction: runs whose font size exceeds the page's body-median by a
      threshold become `## ` headings (or `# ` for the title-sized first run); when font
      signals are absent, fall back to line-shape heuristics (short lines, all-caps
      patterns); **never** emit flat text silently — if no heading rule fires, count and
      record the drop.
    - Table reconstruction: detect multi-column line runs (consistent x-alignment across
      consecutive lines) and emit GFM pipe tables; un-reconstructable tables are dropped
      with a recorded count, never merged into prose.
    - Value line-join: within a text line, when a numeric token is broken across a wrapped
      line (line ends mid-digit or mid-decimal), join before emitting (the P1 test's case).
    - Determinism: pure functions over the extracted runs; no randomness, no clocks, no
      cwd/temp dependence; no network anywhere.
  - `tests/pdf/test_convert.py` — extend to GREEN: the P1 cases pass; add a determinism
    test (same bytes → same str, in-process).
- **Validation:** `uv run pytest tests/pdf/` green; `uv run pytest tests/extract/`
  untouched and green; `uv run pytest tests/test_no_network.py` green.
- **Commit:** `Implement deterministic PDF-to-markdown converter on pinned pypdf`

## Testing strategy

- Unit tests: heading detection (font-size and fallback paths), table line detection, value
  line-join, determinism (in-process + cross-process), no-network source guard.
- The existing suites (`tests/extract/`, `test_no_network.py`, `test_determinism.py`) must
  stay green throughout — the converter lives outside `src/plumb/extract/` so the AST
  allowlist is untouched, but the autouse network blocker covers it.
- Fixture-dependent tests use `fixtures/papers/PMC*.pdf` from the fixtures aspect; the
  handcrafted line-join case is unit-level.

## Environment & determinism

- pypdf pinned exactly; no other runtime deps. `uv sync` then `uv run pytest` from the
  worktree root.
- Determinism contract: identical input bytes → identical output str, across processes and
  hash seeds. pypdf extraction is deterministic for fixed bytes; the pin makes that claim
  honest against future pypdf releases.
- No env vars, no BYOK, no network paths in this aspect.

## Edge cases & error handling

- Unreadable/corrupt PDF bytes → raise a named exception (`PdfInputError`) with the cause;
  this is a harness-side failure, so downstream verdicts (C4, later) would be `UNVERIFIED`
  with a named cause — the converter itself emits no verdicts.
- Font signals absent → fallback heading heuristics, with drops counted (surfaced to the
  seam tests via a recorded count, per spec).
- Values split across lines → join rule (P1 test).
- Ligatures/hyphenation in prose: numbers are the only tokens that matter for claim ids;
  the join rule is numeric-token-scoped, never whole-word, to avoid inventing words.
