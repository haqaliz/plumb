## Design decisions (locked, with two flagged deltas from the specs)

1. **Record validation = the replay chain.** The bank re-uses `replay.read_record`
   (promoted from `replay._read_record`, `src/plumb/cli/replay.py:96-124`) — strict member
   reading, `parse_trace` run-id check, curated-claims re-admission against the record's own
   paper — then `verify_claims` re-derivation and the byte-identical `verdicts.json`
   cross-check (promoted `replay.cross_check`, `replay.py:172-180`). A record that fails any
   of it is refused; nothing is banked. **Delta 1:** the two replay helpers become public
   names (the corpus command is a real second consumer; behavior is pinned by the existing
   replay tests, which exercise behavior, not names).
2. **Non-claims lane = verbatim transport.** The record's `unrepresentable.json` (the gate
   record's non-claim document, `{unrepresentable: [{section, text, context, start, end,
   reason}]}`) is staged as the case's `nonclaims.json` **verbatim** (its internal shape is
   the benchmark aspect's to read). Staging: a transient dir holding exactly the lanes
   (`claims/bindings/trace/verdicts/objects/paper` + `nonclaims.json`) — `bank_case` reads a
   record dir, and the store stays generic (no gate-record naming inside it).
3. **Labels = record-side `labels.json`, validated, transported.** The bank reads an
   optional `labels.json` beside the record (human-authored), validates it against the
   re-admitted claim ids (keys ⊆ claim ids, values ∈ {`confirmed`, `refuted`}; malformed →
   `RECORD_INVALID`), and passes it to `bank_case`. The bank **transports, never creates**:
   no labels file → no `labels.json` written. **Delta 2 (store manifest):** the store's
   manifest gains `labels_hash: str | None` alongside `has_labels`. Rationale: without it,
   two banks of the same record with *different label values* would compare manifests equal
   and no-op silently — a silent pass, which the honesty contract forbids. `labels_hash` is
   part of the **manifest** (mutation detection is complete: `read_case` verifies
   `labels.json` bytes against it, `CASE_TAMPERED` on mismatch) but **never part of
   `case_id`** (identity stays the record — pinned by test). `has_labels` ≡
   (`labels_hash` is not None); disagreement is `CASE_INVALID`. The Phase-3 schema-pin tests
   are updated to the new key set (they pin the contract; the contract evolves deliberately).
4. **Shell surface.** `plumb corpus bank <record-dir> [--store DIR]` — a new `corpus`
   subcommand with a nested `bank` subparser; `--store` defaults to `corpus/local/`. New CLI
   cause `CORPUS_REFUSED` in `CLI_CAUSES` + `(CorpusRefused, CORPUS_REFUSED)` in
   `_CAUSE_MAP` (before the `ValueError` → `RECORD_INVALID` fallback — `CorpusRefused` is a
   `ValueError` subclass). Exit 0 banked/no-op; 1 refusal (named cause); 2 usage. Output:
   `banked <case_id>` or `already banked: <case_id>` (deterministic — case_id is
   content-addressed).
5. **Case #1's label source.** `fixtures/gate/agrodesign/labels.json` is added — the
   machine-readable form of the owner's review (`README.md:75-82`, `review_required`,
   confirmed 2026-09-27): `{"<diverged claim_id>": "confirmed"}`. Human-authored; the bank
   only transports it. The gate record's other members are untouched.

## Testing strategy

- Strict TDD per phase; house patterns: in-process `main()` calls for exit codes
  (`tests/cli/test_replay.py:146`), mutation-checked guards where a rule is load-bearing,
  no-network autouse blocker (`tests/conftest.py:56-60`).
- The gate integration test is the honest end-to-end: real committed bytes, byte-identity,
  re-derivation from stored trace only — no re-run, no network.
- Full suite green after every phase (1769 + new).

## Environment & determinism

- No env vars, no network, `UV_OFFLINE` untouched. `tempfile` staging is transient (case
  bytes derive from the record's bytes only — the temp path never reaches the case).
- New canonical artifacts (`labels.json`, manifest `labels_hash`) follow the house rules;
  the determinism guards from store Phase 3 already scan the package source (tempfile is
  NOT in `src/plumb/corpus/`'s forbidden list; the CLI module is not scanned — verify the
  guards still pass).

## Edge cases & error handling

- Record without `verdicts.json` → cross-check skips (the `cross_check` precedent); bank
  still proceeds on re-derived verdicts.
- Record without `unrepresentable.json` → no `nonclaims` lane.
- Record without `labels.json` → no labels, `has_labels` false (bank transports, never
  creates).
- Labels with unknown claim ids / invalid values → `RECORD_INVALID`, nothing banked.
- Re-bank same record + same labels → no-op; different labels → `CASE_CONFLICT` (exit 1,
  `CORPUS_REFUSED`), existing case untouched.
- Tampered committed `verdicts.json` → `RECORD_INVALID` via the cross-check; nothing banked.
- `CorpusRefused` maps to `CORPUS_REFUSED` (its `.cause` names `CASE_CONFLICT` /
  `CASE_TAMPERED` / `CASE_INVALID` in the detail).
