## Design decisions (locked)

- **Case layout** under `<store>/<case_id>/`: `case.json` (manifest) + member bytes
  `claims.json`, `bindings.json`, `trace.json`, `verdicts.json`, optional `nonclaims.json`,
  optional `labels.json`, and `objects/` (SHA-256-named, locatable only).
- **`case_id`** = SHA-256 over canonical JSON of `[format, paper_hash (or null), run_id,
  sorted member hashes {claims, bindings, trace, verdicts, nonclaims?}, objects_tree_hash]` —
  `derive_run_id` style (`src/plumb/run/trace.py:69-75`). **Labels are outside identity**:
  identity is the record; labels are human annotations transported at bank time (label values
  never enter `case_id`).
- **`objects_tree_hash`** = SHA-256 over canonical JSON of the sorted list of object SHA-256s.
  Duplicate object bytes collapse by construction (files are hash-named).
- **`paper_hash`** = SHA-256 of the record's paper file when present, else null (None vs ""
  distinct, house style).
- **Manifest** `case.json`: format `plumb-corpus-case/1`, case_id, paper_hash, run_id, member
  hashes, objects_tree_hash, `has_labels: bool`. Canonical JSON: sorted keys, no incidental
  whitespace, `ensure_ascii=False`, `allow_nan=False`, one trailing newline. **No timestamps,
  no absolute paths** (byte-identical across processes — the house determinism contract).
- **Store semantics:** write-once. Re-bank with identical member hashes → **no-op** (same
  case_id, nothing written). Same case_id, different bytes → **refused** (`CASE_CONFLICT`),
  existing case untouched. Read-back verifies every member hash; mismatch → `CASE_TAMPERED`,
  never forged bytes. A *new* case whose write fails verification is cleaned up (it was never
  a case); an *existing* case is never touched.
- **Causes** (`src/plumb/corpus/causes.py`, house style): `CASE_CONFLICT`, `CASE_TAMPERED`,
  `CASE_INVALID` (malformed manifest/members). Closed frozenset + catalogue test like
  `tests/verify/test_cause_catalogue.py`.
- **Public seam** (`src/plumb/corpus/__init__.py`): `bank_case(...)`, `read_case(...)`,
  `derive_case_id(...)`, causes export. No other imports from `plumb.corpus` internals.

## Implementation phases

### Phase 1 — Case format: manifest, case_id, canonical bytes

- **Goal:** the case record + identity + serializer, all deterministic.
- **Prerequisites:** none.
- **Files:**
  - `tests/corpus/test_case.py` — **written first (RED)**: case_id determinism (identical
    members → identical id; any member differing → different id; labels never affect id);
    manifest serialization canonical (sorted keys, trailing newline, no timestamps/abs paths);
    paper_hash null-vs-value distinct; objects_tree_hash deterministic over sorted set.
  - `src/plumb/corpus/causes.py` — closed vocabulary (`CASE_CONFLICT`, `CASE_TAMPERED`,
    `CASE_INVALID`).
  - `src/plumb/corpus/case.py` — `Case` manifest record, `derive_case_id`, canonical
    serializer (house `_JSON` options + `_refuse` hook), member-hash helpers.
- **Validation:** `uv run pytest tests/corpus/test_case.py` green; existing suite untouched.
- **Commit:** `feat(corpus-store): case format, content-addressed case_id, canonical bytes (case-format)`

### Phase 2 — Store semantics: bank, no-op, conflict, tamper

- **Goal:** `bank_case` / `read_case` with write-once semantics.
- **Prerequisites:** Phase 1.
- **Files:**
  - `tests/corpus/record_helpers.py` — synthetic record builder (minimal valid claims/
    bindings/trace/verdicts/objects; can reuse `tests/verify/verify_helpers.py` + real C3
    helpers where cheap).
  - `tests/corpus/test_store.py` — **written first (RED)**: round-trip byte-identity; re-bank

    new-case write failure cleans up; objects duplicates collapse; no labels.json → case has
    `has_labels: false`.
  - `src/plumb/corpus/store.py` — `bank_case(members, store_dir)`, `read_case(case_dir)`.
  - `src/plumb/corpus/__init__.py` — public seam + causes export.
- **Validation:** `uv run pytest tests/corpus/` green; `uv run pytest` full suite green.
- **Commit:** `feat(corpus-store): bank_case write-once — no-op, conflict refusal, tamper-detecting read (store-semantics)`

### Phase 3 — Determinism guards

- **Goal:** cross-process byte identity pinned in the house style.
- **Prerequisites:** Phase 2.
- **Files:**
  - `tests/corpus/test_corpus_determinism.py` — **written first (RED)**: manifest + case

    (path-qualified key sets, both-direction assertions); source guards (no
    float/hash/clock/env/random in `src/plumb/corpus/`).

- **Validation:** `uv run pytest` full suite green (1684 + new), no-network autouse blocker
  intact.
- **Commit:** `test(corpus-store): cross-process determinism and schema guards (determinism)`

## Environment & determinism

- No env vars, no external tools, no network. `UV_OFFLINE` untouched.
- Determinism is the point of this aspect: canonical bytes, no timestamps, no absolute paths,
  no `float`/`hash()`/`id()`/clock/env/random in the package (guard-enforced).

## Edge cases & error handling

- Record without paper → `paper_hash: null` (distinct from a hash).
- Record without nonclaims → member absent; member hashes only for present members.
- Empty objects/ → objects_tree_hash over `[]` (deterministic).
- Duplicate object bytes → collapse in `objects/` (hash-named).
- New-case write failure → cleanup, raise `CASE_INVALID`; existing-case conflict → raise
  `CASE_CONFLICT` without touching bytes; tampered member on read → `CASE_TAMPERED`.
- No `labels.json` in this aspect's writes — `has_labels` is always `false` here; the `bank`
  aspect transports labels (identity never includes label values).
