## Design decisions (locked; one pinned interpretation from the spec's open question)

1. **Verdict read-back.** No `parse_verdicts` exists today — the metrics module carries a
   strict minimal reader of the canonical `verdicts.json` (`{run_id, coverage, verdicts}`,
   each verdict with `claim_id`, `verdict`, `bound`): any other shape, missing key, or
   wrong type is refused (ValueError → the caller's named-cause path). It reads what metrics
   needs and no more; a full typed `VerdictSet` read-back is out of scope.
2. **Coverage** = the C4 bound definition (`docs/planning/binding-verdict/prd.md:179-181`):
   a claim is bound when a value was located and parsed, whatever the verdict (`Verdict.bound`,
   `src/plumb/verify/verdict.py:112`). `UNVERIFIED` claims count in the claims total and are
   never bound; they are never folded into any pass/fail rate.
3. **Precision on `DIVERGED`** = confirmed / (confirmed + refuted), per claim, over the
   engine-`DIVERGED` claims **that carry a label**; an unlabeled `DIVERGED` is counted in
   neither numerator nor denominator. If no `DIVERGED` is labeled, precision is not a rate —
   rendered as `no labeled DIVERGEDs`, never `0/0` and never a bare number.
4. **Recall** = confirmed-`DIVERGED` / flagged problems. **Pinned interpretation for this
   slice** (the spec's open question): "flagged" = any claim with a label (whatever its
   verdict — a human attaching a label to a non-`DIVERGED` claim is flagging a potential
   miss). Fuller miss-detection semantics (labels on `REPRODUCED` claims as systematic
   extraction-error probes) are a named follow-on, out of scope.
5. **Labels** come from `CaseRead.labels` (the store's verified, hash-checked read — bank
   Phase 1). Values validated at read: `confirmed` / `refuted`; a label keying a claim the
   case's verdicts don't carry is refused (data corruption, never silently dropped).
6. **Label-authority** is a reporting-time declaration: `--authority owner|third-party`
   (default `owner`), carried in the report's JSON and shown next to every precision/recall
   figure (e.g. `1/1 (owner)`). Label files don't carry authorship in this slice (named
   follow-on); the declaration is how the report stays honest about whose labels it measures.
7. **Report surface.** `plumb corpus report [--store DIR] [--authority owner|third-party]
   [--json]`. Store iteration is sorted by `case_id` (deterministic); every `<case_id>`
   directory carrying a `case.json` manifest is a case. A tampered or unreadable case
   refuses the whole report with `CORPUS_REFUSED` naming the case (honest — never a silent
   drop). A missing store dir is `CORPUS_REFUSED`; an empty store renders zeros (0 claims,
   no rates). Exit 0 on report, 1 on refusal, 2 on usage.

## Testing strategy

- Strict TDD; house patterns: in-process `main()`, mutation-checked guards where a rule is
  load-bearing (the n=0 no-rate rule and the unlabeled-exclusion deserve mutation checks),
  no-network autouse blocker.
- The metrics exclusion rules are the load-bearing honesty of this aspect — every rule gets
  a direct test AND a mutation check (remove the exclusion → test fails).
- Full suite green after every phase (1803 + new).

## Environment & determinism

- No env vars, no network. New canonical artifacts (`metrics` JSON, report table/JSON) follow
  the house rules; the corpus source guards (store Phase 3) scan `src/plumb/corpus/` — new
  `metrics.py` must conform (json only; no datetime/os/random). The report's JSON is
  byte-identical across processes and seeds (sorted iteration + canonical bytes).

## Edge cases & error handling

- Store with zero cases → zeros, no rates, exit 0. Store dir missing → `CORPUS_REFUSED`,
  exit 1.
- Tampered case member → `read_case` refuses → report refuses, naming the case and cause,
  exit 1 (`CORPUS_REFUSED`). Never a silent skip.
- Labels keying unknown claims → refused (corruption, not ignored).
- Unlabeled `DIVERGED` → excluded from precision both sides (shown in coverage/by-verdict).
- `UNVERIFIED` claims → coverage denominator only, never bound, never pass/fail.
- No labeled `DIVERGED`s → `no labeled DIVERGEDs`, never `0/0` or a bare rate.
