## Testing strategy

- Offline, in-process CLI (`main(argv)`), monkeypatched `WORK_ROOT`; the stub `jupyter` is a
  local executable the test writes — no kernel, no network.
- Determinism by the existing cross-run comparison pattern.
- The probe is the only place a real kernel runs; it is dev-time and never imported by tests.

## Environment & determinism

- No new deps. The e2e relies on PATH being inherited when the checkout has no `.venv`
  (`--no-env-build`); the runner prefixes `.venv/bin` only when present.
- The probe builds a real env with network access at dev time — the `tools/demo_env_build.py`
  precedent.

## Edge cases & error handling

- Stub exits nonzero → runner maps `WONT_RUN` (already covered by runner tests; do not
  re-test here unless a notebook-specific path appears).
- If the CLI e2e cannot see the stub on PATH (env scrub), assert the mechanism rather than
  weakening the scrub — the scrub removes secret-bearing names only.
