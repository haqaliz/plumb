## Phases

### Phase E1: root notebook scan (RED → GREEN)

- **Goal:** `ManifestScan.notebooks` records root-level `*.ipynb`, sorted; nested paths are
  not candidates.
- **Files:**
  - `tests/intake/test_env.py` — failing tests: `ALL_MANIFESTS` adds `analysis.ipynb` and
    `test_detects_every_manifest_present` asserts `scan.notebooks == (Path("analysis.ipynb"),)`;
    `test_reports_absence_as_none` asserts `scan.notebooks == ()`; a new test asserts
    `sub/analysis.ipynb` and `.ipynb_checkpoints/analysis-checkpoint.ipynb` are not
    candidates and that two root notebooks sort.
  - `src/plumb/intake/manifest.py` — add the field and
    `tuple(p.relative_to(root) for p in sorted(root.glob("*.ipynb")))`; update the dataclass
    and module docstrings (the manifest list).
- **Validation:** `uv run pytest tests/intake/ -q` green; `uv run pytest -q` green.
- **Commit:** `Scan root notebooks: ManifestScan gains notebooks, root-only`

### Phase E2: fallback notebook resolution (RED → GREEN)

- **Goal:** `resolve_entrypoint` resolves a single root notebook when the existing rules find
  nothing, with `source="notebook"` and the exact argv; ambiguity/missing stay named causes.
- **Files:**
  - `tests/run/test_entrypoint.py` — failing tests (new `TestNotebooks`):
    a single root `analysis.ipynb` → argv
    `("jupyter","nbconvert","--to","notebook","--execute","--inplace","analysis.ipynb")`,
    `source == "notebook"`; two root notebooks → `EntryPointAmbiguous` carrying both argvs;
    notebook + `main.py` → `main.py` wins; notebook + one script → `pyproject-script` wins;
    a nested notebook only → `EntryPointMissing`; a module-docstring/rule-list update is not
    asserted, behavior only.
  - `src/plumb/run/entrypoint.py` — collect notebook candidates **only when the
    scripts/main.py pass produced none** (fallback; kinds never mixed), reusing the existing
    ambiguity/missing logic; update the module docstring rules and the `source` comment to
    include `"notebook"`.
- **Validation:** `uv run pytest tests/run/test_entrypoint.py -q` green; `uv run pytest -q`
  green.
- **Commit:** `Resolve notebook entry points as the fallback rule, never a guess`

## Testing strategy

- Failing test first in every phase; run it, see RED, then implement.
- Offline only; synthetic checkouts via the existing `make_checkout` helpers; no subprocess.
- Regression: the full 1913-test suite stays green — this aspect must not touch runner,
  capture, trace, CLI, or any cause vocabulary.

## Environment & determinism

- No new deps. `ManifestScan`'s new field is additive; `describe_environment` and the env
  descriptor are untouched. Paths are relative (`Path("analysis.ipynb")`), matching the
  existing `requirements`/`main_py` records.

## Edge cases & error handling

- Multiple root notebooks → `ENTRYPOINT_AMBIGUOUS`; a notebook next to a script/main.py is
  shadowed, never ambiguous; nested notebooks are invisible to discovery (never guessed).
- An unreadable `pyproject.toml` keeps its current behavior: `ENTRYPOINT_MISSING` before any
  notebook fallback (a hidden script is never bypassed).
