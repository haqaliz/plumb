## What this proves

- **A `notebook_cell`-bound claim decides through the live CLI.** The paper's one
  headline claim (`0.87`) binds to `analysis.ipynb#cell-0` and is `REPRODUCED`: the
  cell's `execute_result` `data.text/plain[0]` leaf reads verbatim `0.87`, becomes the
  strict `Decimal` 0.87, and sits inside the [0.865, 0.875] band the paper's written
  precision defines. The probe's second claim (`0.42`) binds to the same cell and is
  `DIVERGED` (delta 0.45, band [0.415, 0.425]) — the same located value, two paper
  values, both decided. The stub notebook writes a stream line too, and it lives in the
  same canonical cell artifact; the pointer `/1/data/text/plain/0` walks index 1 (the
  `execute_result`), the D1 literal-`/` keys form.
- **The evidence bytes are the content-addressed cell projection.** Both verdicts cite
  sha `8aaf68cd7016fd72…` — the 174-byte canonical projection of the cell's `outputs`
  array (sorted keys, compact separators, one trailing newline; the stream line is
  visible in it above). It was read through `Capture.read` by hash, never from a stale
  output. The whole executed notebook is captured alongside (499 bytes, sha
  `00bc507ebd80ec80…`) as the provenance artifact; the run's stdout (50 B — the stub's
  progress line) and empty stderr are the two `bytes` objects.
- **The stub mechanism.** `jupyter` on PATH is a POSIX-sh executable that rewrites
  `analysis.ipynb` inside the run's working copy with a fabricated executed notebook
  (the same cell, its outputs filled) and prints one progress line. The runner resolves
  the fallback entry point `jupyter nbconvert --to notebook --execute --inplace
  analysis.ipynb` to it through the scrubbed env, which inherits the probe's PATH. **No
  kernel ran and nothing touched the network**: `--no-env-build` stubs the environment
  build, the runner sets `UV_OFFLINE=1`, and `WORK_ROOT` was a fresh temp dir (the
  dev-machine paths in the run's own lines above are never recorded by the spine).
- **Determinism.** Two runs gave the identical run slot (`run-9de59da8d3db-ddd498b8`),
  run id, object hashes and verdict document: the deterministic spine plus a
  deterministic stub reproduce byte-for-byte.

## Honest limits

- One synthetic notebook, one machine, one branch state. The stub fabricates the cell
  outputs rather than a kernel computing them — a real kernel's whole-file notebook
  bytes proved run-variable in the capture precedent
  (`docs/planning/notebook-capture/spine/probe_20261008.md`), while the cell projection
  was the hash-stable, bindable artifact; the binding here targets that projection.
- The verdicts prove the locator seam on a hand-written binding — not claim selection,
  not a real paper, and not the proposer (none exists).
- Nothing was banked and no corpus number moves; record/replay/bank/bundle round-trips
  of this binding are pinned by the test suite (`tests/cli`, `tests/bundle`), not by
  this probe.
