## Phases

### Phase I1: tree hashing (RED → GREEN)

- **Goal:** `plumb_tree_hash(dir) -> TreeHash("plumb", digest)` and the git variant
  `git_tree_hash(dir) -> TreeHash("git-tree", digest)`.
- **Files:**
  - `tests/intake/test_tree.py` — failing tests: hash stable across runs and processes
    (subprocess pattern); input is sorted `(relpath, bytes)` only (mtime touch does not
    change the hash); `.git` excluded; empty dir hashes; a git repo's `HEAD^{tree}` matches
    the plumb-tree hash of a checkout of the same tree (when feasible) or is stable for the
    same rev.
  - `src/plumb/intake/tree.py` — walk sorted, hash bytes only; git via `git rev-parse
    HEAD^{tree}` subprocess (captured, offline).
- **Validation:** `uv run pytest tests/intake/` green; full suite green.
- **Commit:** `Hash repo trees deterministically (plumb + git-tree schemes)`

### Phase I2: source resolution (RED → GREEN)

- **Goal:** `resolve_local(path)`, `resolve_git(url, rev=None)`, `resolve_archive(path)` →
  `Checkout(checkout_dir, tree_hash, source_record)`.
- **Files:**
  - `tests/intake/test_checkout.py` — failing tests: local dir resolves + hashes; git URL
    with `file://` clone + `--rev` checkout (branch, tag, and SHA) resolves and records
    `HEAD^{tree}`; `rev` default = default branch (N1), recorded; archive (tar.gz and zip,
    synthesized in tests) extracts to a checkout dir with plumb tree hash; named failures:
    missing path → `SourceNotFound`, unknown rev → `RevNotFound`, bad archive →
    `UnsupportedArchive`.
  - `src/plumb/intake/checkout.py` — stdlib only; git via subprocess (`git clone file://`,
    `git checkout <rev>`); archive via `tarfile`/`zipfile` with a recorded size cap (not
    enforced yet — follow-on).
- **Validation:** `uv run pytest tests/intake/` green; full suite green.
- **Commit:** `Resolve local paths, git URLs, and archives to pinned checkouts`

### Phase I3: manifest scan + env descriptor (RED → GREEN)

- **Goal:** `scan_manifests(checkout)` and `describe_environment(checkout) -> EnvDescriptor`
  (python pin; policy lockfile-first → declared → best-effort; policy recorded; tool versions
  `git --version`/`uv --version` recorded; isolation posture recorded).
- **Files:**
  - `tests/intake/test_env.py` — failing tests: lockfile-first when `uv.lock` +

    `EnvBuildFailed` on a failing stub.
  - `src/plumb/intake/env.py` (descriptor + runner seam), `src/plumb/intake/manifest.py`.
- **Validation:** `uv run pytest tests/intake/` green; full suite green.
- **Commit:** `Describe environments: lockfile-first policy, posture, tool versions`

## Testing strategy

- Offline only: `file://` git repos and synthetic archives in tmp dirs; env runner stubbed;
  subprocess allowed (conftest gap); no sockets.
- Determinism: tree hash cross-process stability; mtime-insensitivity.
- The real `uv sync` runs only in `tools/demo_env_build.py` at dev time.

## Environment & determinism

- No new deps. External tools `git`/`uv` recorded by version in the descriptor.
- Hash inputs are sorted bytes only; no mtimes, no order dependence.

## Edge cases & error handling

- Named causes: `SourceNotFound`, `RevNotFound`, `UnsupportedArchive`, `EnvBuildFailed` —
  each maps to a future `UNVERIFIED` cause (documented in the module docstring); never
  silent.
- Size caps recorded, enforcement deferred (named follow-on).
- Git sources record `HEAD^{tree}`; non-git record plumb tree hash; scheme field on
  `TreeHash` reconciles both.
