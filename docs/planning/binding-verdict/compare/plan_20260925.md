## Phases

### Phase C1: Decision type, kind and scale gates (RED → GREEN)

- **Files:** `src/plumb/verify/compare.py`, `tests/verify/test_compare.py`.
- **API:**
  - `REPRODUCED`, `WITHIN_TOLERANCE = "WITHIN-TOLERANCE"`, `DIVERGED`, `UNVERIFIED` constants
    (in `compare.py`; re-exported by the seam).
  - `Decision(verdict, cause: str | None, rederived: Decimal | None, band: tuple[Decimal,
    Decimal] | None, tolerance_band: tuple[Decimal, Decimal] | None, delta: Decimal | None)`.
  - `decide(reported: ClaimValue, units: str | None, located: Decimal, located_half_unit:
    Decimal, tolerance: Tolerance | None, scale: Decimal | None) -> Decision`.
- **Rules:** `type()` check — any `float` argument (or a `Decimal` field that isn't) →
  `TypeError`. Kind gate → `UNSUPPORTED_VALUE_KIND`. Percent (`units == "%"` or `"%" in
  reported.text`) without scale → `UNIT_UNDECLARED`. `rederived = located × scale`,
  `artifact_half = located_half_unit × scale` (both in `CONTEXT`).
- **Tests first:** criteria 6, 9, 10.
- **Commit:** `Compare: decision record, value-kind and percent-scale gates`

### Phase C2: Point — band, D1a, D7, tolerance (RED → GREEN)

- **Order (pinned; the docstring says so):**
  1. D1a: the paper wrote no decimal places (`v.as_tuple().exponent == 0`), `v != 0`, and the
     last written digit is zero (`v.normalize().as_tuple().exponent > 0`, e.g. `10000` →
     `1E+4`), with no tolerance → `PRECISION_AMBIGUOUS`. (`1.5e3` has exponent 2 — written in
     scientific notation, its precision is stated, so it is not ambiguous.)
  2. `h = half_unit(v)`; band `[v−h, v+h]` closed; `rederived` in band → `REPRODUCED`.
  3. D7: `artifact_half > h` and `v ∈ [re−a, re+a]` → `UNVERIFIED: ARTIFACT_PRECISION_COARSER`.
  4. Tolerance: `abs` → `[v−t, v+t]`; `rel` → `v == 0` ⇒ `NO_TOLERANCE`, else
     `[v−r·|v|, v+r·|v|]`; inside → `WITHIN_TOLERANCE`.
  5. Else `DIVERGED`.
  `delta = re − v` on every decision past the gates.
- **Note D1a subtlety:** `Decimal("10,000".replace(",", ""))` = `Decimal("10000")` with
  exponent 0; the "ends in zero" test is on the digits, so `12` → not ambiguous, `10` →
  ambiguous, `100.0` (exponent −1) → **not** ambiguous (the paper wrote a decimal place).
- **Tests first:** criteria 1–5, 7 (Point parts).
- **Commit:** `Compare points: written-precision band, coarse artifacts, explicit tolerance`

### Phase C3: Bound (RED → GREEN)

- `op` satisfied by `re` vs `m` → `REPRODUCED` (band `None`, recorded threshold).
- D7 for bounds: `artifact_half > 0` and `[re−a, re+a]` contains points on both sides of the
  threshold (i.e. the op is satisfied at one end and not at the other) and `re` does not satisfy
  → `ARTIFACT_PRECISION_COARSER`.
- Tolerance: widen threshold permissively (`<`/`<=`: `m + w`; `>`/`>=`: `m − w`; `w = t` or
  `r·|m|`, `m == 0` with `rel` → `NO_TOLERANCE`); satisfied → `WITHIN_TOLERANCE`.
- Else `DIVERGED`.
- **Tests first:** criterion 8 (every op), bound D7 case (`p < 0.001`, located `"0.001"` at
  `.3f` → half-unit 0.0005 → straddles → coarser).
- **Commit:** `Compare bounds: operator, widened threshold, coarse artifacts`

### Phase C4: hostile context (RED → GREEN)

- Test criterion 11: run the criterion 1–8 table inside `localcontext(Context(prec=3,
  rounding=ROUND_FLOOR))` and assert identical `Decision`s. Fix by routing every arithmetic
  call through `numbers.CONTEXT`.
- **Commit:** `Pin compare arithmetic to a local decimal context`

## File-by-file build order

1. `src/plumb/verify/compare.py` — `Decision`, `decide`, verdict constants; deps
   `plumb.extract.value`, `verify.causes`, `verify.numbers` (incl. `Tolerance`, placed in V0
   so this aspect never waits on `locators` L1).
2. `tests/verify/test_compare.py` — table-driven, one row per spec criterion.

## Testing strategy

Pure unit tests; no I/O. Build `Point`/`Bound` via `plumb.extract.value.parse_value` so
reported values carry real paper-shaped text and exponents. `uv run pytest
tests/verify/test_compare.py`.

## Environment & determinism

Pure function; the pinned context removes the only ambient input (thread decimal context).
`Inexact` trapped: an inexact operation raises `decimal.Inexact` — a harness bug, propagated,
never a verdict (V0's 40-digit / exponent limits keep real inputs exact).

## Edge cases

`-0` vs `0`; negative reported values (band symmetric, `rel` uses `|v|`); `Bound` with `>=`
and equality; `scale` of `1`; a zero tolerance (`abs "0"`) behaves as no widening.
