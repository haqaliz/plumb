# Implementation plan — `binding-verdict` / `verdict-seam` (2026-09-25)

Sources: [`../prd.md`](../prd.md) (M4–M8, S1–S3; D5), [`spec.md`](spec.md). Capability C4.
**Prerequisites:** `locators` (V0, L1, L2) and `compare` (C1–C4) merged on the branch.

## Phases

### Phase S1: the Verdict record (RED → GREEN)

- **Files:** `src/plumb/verify/verdict.py`, `tests/verify/test_verdict.py`.
- **API:** frozen `Verdict(claim_id, verdict, cause, reported_text, located_text,
  rederived: Decimal | None, band, tolerance_band, delta, locator: dict | None, relpath,
  sha256, run_id)`; property `review_required = verdict == DIVERGED`.
- **`__post_init__` refuses:** unknown verdict; `UNVERIFIED` without cause / non-`UNVERIFIED`
  with cause; cause ∉ `CAUSES`; non-`UNVERIFIED` missing any of `located_text`, `rederived`,
  `sha256`, `run_id`, and (`band` or `tolerance_band` or a `Bound` threshold record); a
  `float` in any field.
- **Tests:** spec criterion 6.
- **Commit:** `Verdict record refuses a verdict without its evidence`

### Phase S2: verify_claims and precedence (RED → GREEN)

- **Files:** `src/plumb/verify/__init__.py` (seam + docstring cause table modelled on
  `src/plumb/run/__init__.py`), `tests/verify/test_verify_seam.py`.
- **API:** `Completed(trace: RunTrace, capture: Capture)`, `NoRun(cause)` with
  `NoRun.from_exception(exc)` (`EntryPointMissing`/`EntryPointAmbiguous` → `exc.cause`;
  `EnvBuildFailed` → `ENV_BUILD_FAILED`, it has no `cause` attribute; anything else →
  `TypeError`); `verify_claims(claims, bindings, run) -> VerdictSet`.
- **Structure (patchable for the mutation check):** `_run_level_cause(run) -> str | None`
  implements precedence steps 1–3; `_verify_one(claim, binding, run) -> Verdict` does step 4
  via `locate` then `decide`. `verify_claims` checks `derive_run_id(trace.argv,
  trace.tree_hash, capture.artifacts) == trace.run_id` (else `ValueError`), refuses duplicate
  claim ids (`BindingInvalid`), and returns records sorted by `claim_id`.
- **Tests:** spec criteria 1, 4, 5.
- **Commit:** `Verify claims against a run: one verdict per claim, run causes first`

### Phase S3: the false-DIVERGED guard + mutation check (RED → GREEN)

- **Files:** `tests/verify/test_false_diverged_guard.py`.
- `_assert_guard(verify)`: builds, for each C3 cause, a run whose outputs *would* diverge
  (fixture repo writes `{"auc": 0.95}` against a paper `0.87`), calls `verify`, and asserts
  every record is `UNVERIFIED` with the expected cause. Cases: `NoRun` ×3; `WONT_RUN`
  (`sys.exit(3)` after writing the JSON); `TIMEOUT` (writes JSON then sleeps past a 1 s
  timeout); `NO_ARTIFACT` (silent program); `STALE_ARTIFACT` (committed back-dated JSON, run
  doesn't touch it).
- Test 1: `_assert_guard(verify_claims)` passes.
- Mutation tests: `monkeypatch.setattr(plumb.verify, "_run_level_cause", lambda run: None)`
  → `pytest.raises(AssertionError): _assert_guard(...)`; `monkeypatch.setattr(
  plumb.verify.locate, "_stale_target", lambda *a: False)` combined with a patched
  `Capture` stale→locatable view → `pytest.raises(AssertionError)`.
  (If making the stale mutation observable needs the stale file to be readable, the mutation
  test writes the same bytes into the store — document the construction inline.)
- **Commit:** `Guard: no C3 failure ever becomes DIVERGED (mutation-checked)`

### Phase S4: serialization + coverage (RED → GREEN)

- **Files:** `src/plumb/verify/serialize.py`, `tests/verify/test_serialize.py`.
- `coverage(verdicts) -> dict` (claims, bound, by_verdict, by_cause — derived only);
  `serialize_verdicts(verdict_set) -> bytes` with the `run.trace` `_JSON` options, a
  registry encoder (`Decimal` → `str`, tuple → list, refuse everything else incl. `float`).
  `VerdictSet(run_id, verdicts, coverage)` lives in `verdict.py`.
- **Tests:** criterion 7 (subprocess byte identity via `sys.executable -c`, like
  `tests/run/test_trace.py`), criterion 8, no `started_at_ns`/absolute path in bytes.
- **Commit:** `Serialize verdicts canonically with a derived coverage summary`

### Phase S5: end-to-end + docs (RED → GREEN)

- **Files:** `tests/verify/test_e2e.py`, `README.md`, `CLAUDE.md`,
  `docs/technical/CAPABILITY_ROADMAP.md` (C4 status), `docs/technical/ARCHITECTURE.md` (C4
  status, the `REPRODUCED` row revised per D1, tolerance/locator open questions marked resolved
  for this slice, cause list synced to M5).
- E2E: spec criterion 9, through `resolve_local` → `run_and_capture` → `verify_claims`, claims
  from `parse_value`. Status prose must say plainly: verdicts are emitted on **synthetic
  repos only**; the Phase 0 gate is **not met** (no real gate paper).
- **Commit:** `Wire C4 end to end on a synthetic repo; docs`

## File-by-file build order

1. `src/plumb/verify/verdict.py` — `Verdict`, `VerdictSet`; deps causes, compare constants.
2. `src/plumb/verify/__init__.py` — `Completed`, `NoRun`, `verify_claims`; deps all.
3. `tests/verify/test_false_diverged_guard.py` — load-bearing.
4. `src/plumb/verify/serialize.py` — canonical bytes, coverage.
5. `tests/verify/test_e2e.py`, docs.

## Testing strategy

Unit (S1, S4), seam (S2), guard + mutation (S3), E2E (S5). All offline; subprocesses are local
programs. `uv run pytest` must stay green after every phase (baseline 1130 + new).

## Environment & determinism

No clock on the record (`started_at_ns` stays on the trace, not the verdicts); no absolute
paths; records sorted by `claim_id`; `run_id` from C3. TIMEOUT case uses a 1 s timeout — keep
it the only slow test.

## Edge cases & error handling

Empty claim set → empty verdicts, zero coverage, still serializable. A binding for a claim
with a run-level cause is ignored (run cause governs). `Capture.read` integrity errors
propagate. `PROPOSER_UNGROUNDED`/`MODEL_ONLY_SIGNAL` reserved, never emitted.
