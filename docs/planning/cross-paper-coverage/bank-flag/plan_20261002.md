## Phase 1 — Dual-form claims read (R2)

- **Goal:** `read_record` accepts the C1 record form; curated form untouched.
- **Prerequisites:** none (pure reader change + tests).
- **Files:**
  - `tests/corpus/record_helpers.py` — add `c1_record_dir(...)` (or a `form=` kwarg on
    `record_dir`) writing `claims.json` via `serialize_claims(claims, paper_hash=hash_paper(paper))`
    and carrying `paper.md` (the paper must ground the claim at its span).
  - `tests/cli/test_record_forms.py` — the failing tests first:
    1. C1-form record replays: `read_record` + `verify_claims` + `cross_check` succeed;

       `tests/gate/test_agrodesign_replay.py` pass untouched.

    `{"claims", "paper_hash"}` → `parse_claims(bytes)`; recompute

    normalized_text=normalize_text(paper_text))` (reuse the `paper_text` import already
    at `replay.py:41`); `{"claims"}` → the existing curated path; else `ValueError`.

  from live materials; objects lane carries locatable outputs only.
- **Prerequisites:** Phase 1 (the writer's output must replay through the dual-form
  read).
- **Files:**
  - `tests/cli/test_record_writer.py` — failing tests first (use `verify_helpers`
    `run_full`/`claim`/`writes` via the `sys.path` pattern of
    `tests/corpus/record_helpers.py:26-27`):

       paper_bytes=..., paper_format="markdown")` produces the six required members;
       `--from-record tmp --json` == `serialize_verdicts` of the live verdicts
       (byte-identical).
    2. `objects/` == exactly `capture.locatable` (one hash-named file per locatable
       artifact); an artifact with `diagnostic_only=True` is never copied; the case
       banks with no local paths (scan the record for the tmp path).

       `hash_paper(paper_bytes)`.
    4. Nothing is written into the pinned checkout or the run area (the temp dir is the

    `bindings.json` verbatim, `trace.json` (`serialize_trace`), `verdicts.json`

    `paper_bytes`/`paper_format`. No labels, no nonclaims, no `environment.txt`/`source.json`
    in this phase.

## Phase 3 — `--bank` flag (R3)

- **Goal:** `plumb verify --bank` banks live runs and `--from-record` records; verdicts
  render regardless; refusals are named causes with exit 1.
- **Prerequisites:** Phases 1–2.
- **Files:**
  - `tests/cli/test_bank_flag.py` — failing tests first (reuse the `work_root` fixture
    pattern; redirect the default store with `monkeypatch.chdir(tmp_path)` so
    `corpus/local` resolves into the test):
    1. Live `main(["verify", paper, repo, "--bindings", b, "--no-env-build", "--bank",
       "--json"])` → exit 0, `banked <case_id>` on stdout, case under
       `<tmp>/corpus/local/<case_id>/`; `corpus bank --store <tmp>/corpus/local` on the
       same record → `already banked`, exit 0.
    2. `--from-record --bank` on the AgroDesign fixture (tmp store) → exit 0, banks the
       same case `corpus bank` produces (compare case ids); second run → no-op.
    3. A `NO_ARTIFACT` run (a fixture repo whose entry writes nothing) with `--bank` →
       exit 1, verdicts all `UNVERIFIED`, the case still banks with the run-level cause
       in its `trace.json`.
    4. A bank refusal (store path is a regular file) → exit 1, `CORPUS_REFUSED` on
       stderr, verdicts still rendered on stdout.
    5. `--bank` with `--out` (ephemeral signer key, as `test_live_spine.py:6`) → both
       the bundle and the case are written.
  - `src/plumb/cli/__init__.py` — add `--bank` (action="store_true") beside `--out`
    (`:217-220`), help text; `cmd_verify` validation: allowed in both modes, no new
    exclusions.
  - `src/plumb/cli/live.py` — `_spine` returns the written record dir (or `None`) when
    `args.bank` (write via `write_record` into a `tempfile.TemporaryDirectory` kept
    alive until banking completes); `run_live` renders the verdicts, then banks,
    catching `CorpusRefused` → `CORPUS_REFUSED` and `ValueError` → `RECORD_INVALID`,
    printing the cause line on stderr; exit 0 iff all decided and the bank succeeded.
  - `src/plumb/cli/replay.py` — `replay_record` (and `_replay`) same pattern for
    `--from-record --bank`: render, then `bank_record(record_dir, Path("corpus/local"))`.
- **Validation:** `uv run pytest tests/cli/test_bank_flag.py tests/cli tests/corpus
  tests/gate`
- **Commit:** `feat(cross-paper-coverage): plumb verify --bank closes the
  verify-to-corpus loop`

## Testing strategy

- Unit: per-phase failing tests as listed; the record-form and writer tests exercise
  real C3/C4 bytes (`run_full`, the real serializers).
- Integration: `tests/cli/test_bank_flag.py` through `plumb.cli.main`; the pooled report
  over the real AgroDesign fixture + a live case.
- Fixtures: reuse `tests/cli/fixtures/` (paper.md, bindings.json, repo) and
  `fixtures/gate/agrodesign/`; extend `record_helpers` only.
- Determinism: no clock/network/ordering anywhere; every new byte contract follows the
  house JSON options (`_JSON` triplet, one trailing newline).

## Edge cases and error handling

- C1-form `paper_hash` mismatch → `ValueError` → `RECORD_INVALID` (never a replay).
- Wrong claims-document shape → `ValueError` → `RECORD_INVALID`.
- Bank refusal on the live path → `CORPUS_REFUSED`, verdicts still rendered, exit 1.
- Failed/stubbed run with `--bank` → banks an all-`UNVERIFIED` case (run-level cause in
  the trace), exit 1 — the honest default.
- `--bank` never writes into the pinned checkout or the run area; the temp record is
  removed after banking (TemporaryDirectory scope outlives the bank call only).
- No labels on the live path: the bank transports, never creates (absent `labels.json`
  → no labels lane).
