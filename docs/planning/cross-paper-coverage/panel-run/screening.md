## 1. The selection rule, restated verbatim (spec.md:12-39)

The panel is 3–5 papers (target 4; floor 2 — AgroDesign is case #1 and does not count
toward the floor). A candidate paper qualifies only if **all** of these hold:

1. **License** — paper text openly licensed (CC BY 4.0 or equivalent) so it can be
   committed as a fixture with attribution; code repo public (git URL) at a pinned rev.
2. **Language/runtime** — pure Python (or R) data analysis; runs in laptop-CPU minutes
   (≤ ~20 min).
3. **No run-time network** — data bundled in the repo or generated by the code (seeded);
   nothing fetched during the run.
4. **Machine-readable headline numbers** — the headline quantitative claims (results
   tables, reported statistics) are printed by a script or written as JSON/CSV, so the
   C4 locator types (`json_pointer`, `csv_cell`, `stdout_regex`) can reach them.
   Notebook-only or figure-only results disqualify.
5. **Determinism** — deterministic or explicitly seeded, so re-derivation can match the
   paper's written precision.
6. **Claims rule fixed before binding** — per paper, the claims are defined by a written
   rule (which tables/statements count) BEFORE any run or binding; each claim's text must
   occur verbatim at a found span; unparseable rule members become non-claims with reasons.
7. **Not AgroDesign** (case #1).

Per the spec's open question (spec.md:99-102): the run spine is Python-first, so the
panel defaults to Python papers; R papers are recorded against the rule but are not
selectable until R capture exists.

## 3. Proposed panel of 4 (ranked by fit)

All four are **paper-level qualifiers**: each meets the seven criteria on web-verifiable

### 1. Pingouin — Vallat (2018), JOSS 3(31):1026 — `fixtures/gate/pingouin/`

- **Why it qualifies:** CC BY 4.0 paper text; public Python repo with version tags; the
  paper's code blocks contain **printed numeric outputs** (e.g. the ANOVA example block,
  which the package reproduces verbatim from bundled datasets via `pg.read_dataset`); the
  example datasets ship inside the package (`pingouin/datasets/`) — no network; pure
  deterministic statistics (t-tests, ANOVAs, correlations) on fixed data; seconds of CPU.
- **Likely headline claims:** every numeric value printed in the paper's code-block
  outputs (the t-test and ANOVA examples), plus the stated example statistics in the
  prose; a claim rule of "all numeric cells of the printed example outputs + all stated
  statistics in the §Example section" gives a modest but honest claim count.
- **Repo + suggested pinned rev:** `https://github.com/raphaelvallat/pingouin`, tag
  nearest the paper's date (Nov 2018 — v0.3.x family); exact tag pinned at dev time.
- **Most-likely risk:** headline numbers are *example outputs*, not findings — the claim
  set is small, and a later package version may have changed default behavior; must pin
  the 2018-era rev, and the JOSS PDF's exact printed digits must match the bundled-data
  rerun (first thing the spec generator checks).

### 2. tableone — Pollard et al. (2018), JAMIA Open 1(1):26-31 — `fixtures/gate/tableone/`

- **Why it qualifies:** CC BY 4.0; public Python repo (MIT) with releases; the paper's
  Table 1 (summary statistics of an n=1000 ICU cohort: `68 (53–79)`, `114.25 (40.16)`,
  `864 (86.4)`…) is the *printed output of the package* on a bundled dataset
  (`load_dataset('pn2012')`); deterministic descriptive statistics; the same package
  prints the table to stdout/CSV/LaTeX — a clean `csv_cell`/`stdout_regex` target.
- **Likely headline claims:** every numeric cell of the paper's Table 1 and Table 2, and
  the two printed warning lines (Hartigan Dip Test / Tukey's rule — claimed by the paper
  as generated behavior).
- **Repo + suggested pinned rev:** `https://github.com/tompollard/tableone`, a release
  from the 2018 period (e.g. the 0.7.x/0.8.x era); exact tag at dev time.
- **Most-likely risk:** the paper's Table 1 may have been computed from a MIMIC-III
  subset that is not byte-identical to the bundled `pn2012` dataset (the README's example
  shows `66 [52,78]` vs the paper's `68 (53–79)` for Age — *different* values, so the
  paper's exact numbers may not be re-derivable from the bundled data; if so, bindings
  fail as `UNVERIFIED`, recorded honestly rather than forced).

### 3. Perrin et al. (2024), arXiv:2401.11842 — `fixtures/gate/hte-time-to-event/`

- **Why it qualifies:** CC BY 4.0; public Python repo (Apache-2.0, poetry lockfile — C2's
  lockfile-first policy applies); the benchmark **writes results as CSVs** (`launch_expe.py`
  → `results_expe/raw_results/*.csv`, committed processed results in the repo); data is
  **generated by the code** (synthetic/semi-synthetic DGP, no downloads); the paper's two
  tables carry the headline comparisons (subgroup-detection performance across methods).
- **Likely headline claims:** the numeric results in the paper's two tables (per-method
  performance at the stated ARR points), a rule of "all numeric cells of Tables 1-2";
  prose statistics in the abstract (e.g. detection rates) if present and grounded.
- **Repo + suggested pinned rev:** `https://github.com/owkin/hte` (no tags visible —
  pin the commit SHA of the state matching the paper's configs, recorded in
  `source.json`).
- **Most-likely risk:** Monte-Carlo sampling with no visible seed parameter — if the
  runs are unseeded, the aggregates cannot match the paper's written precision
  (criterion 5 fails at dev time; becomes a documented selection miss, not a forced run).

### 4. Tensorpac — Combrisson et al. (2020), PLOS Comput Biol 16(10):e1008302 — `fixtures/gate/tensorpac/`

- **Why it qualifies:** CC BY 4.0; public Python repo (BSD-3) with a `paper/` folder of
  scripts that regenerate the paper's validation; data is **generated on the fly by the
  code** ("generated on the fly (not loaded from a repository)", stated in the paper's
  Data Availability); the validated pipeline outputs PAC values and statistics
  (ADF stationarity test returns a printed dataframe) — `stdout_regex`-reachable.
- **Likely headline claims:** the stated speed ratios in §"Tensor-based implementation"
  ("between 6 times to more than 12 times faster") if reproducible as printed numbers by
  the paper scripts; the validation PAC values in the figures' captions where a script
  prints them; the rule must be written to count only script-printed values.
- **Repo + suggested pinned rev:** `https://github.com/EtienneCmb/tensorpac`, a release
  from the 2020 period; exact tag at dev time.
- **Most-likely risk:** the paper's headline results are **figure-dominant** (comodulograms,
  time comparisons as plots) — if the paper scripts print no bindable numbers, criterion 4
  fails at dev time; also the synthetic signals draw random noise (`pac_signals_wavelet`
  "extract the phase from a random distribution") — unseeded randomness may break
  criterion 5. It is ranked last for exactly these two risks.

## Paper 1 dev-time probe — Pingouin: documented selection miss (2026-10-02)

Probed by the per-paper agent at dev time (Step A of `plan_20261002.md`), before any
fixture, spec, run or binding. Outcome: **Pingouin fails the selection rule — a documented
selection miss, not forced through.** The floor falls to Perrin et al. (panel rank 2).

### Evidence

- **The published paper contains no quantitative claims.** The JOSS paper
  (doi:10.21105/joss.01026, CC BY 4.0, fetched from
  `https://joss.theoj.org/papers/10.21105/joss.01026.pdf`) is a **one-page, summary-only
  software paper**. `pdf_to_markdown` and pypdf's raw text both give 1 page / ~2.6 KB of
  prose. The only decimal numbers in the entire PDF are `10.21105` (the DOI) and `4.0`
  (the CC-BY license version). There are **no code blocks, no printed outputs, no results
  tables, no reported statistics** — nothing the C4 locators (`json_pointer`,
  `csv_cell`, `stdout_regex`) could reach. PDF SHA-256 (probe copy):
  `9ed4293e0cd7e38259dc35ab06a9cb6ce89f9b1b9f734e769f9a4c9be394d218`.
- **The paper-era repo matches the published text, with no examples.** The repo
  (`github.com/raphaelvallat/pingouin`) at tag **v0.2.1** (= `94fa2414b5f2cab0033da25eab33138912fdc63a`,
  tagged 2018-11-19, the paper's published date — the paper-era release) carries
  `JOSS/paper.md` whose Summary matches the published PDF nearly verbatim; its history (4
  commits, Oct 2018) never added an examples section.
- **The screening's criterion-4 basis is falsified.** The screening recorded
  "pingouin, tableone: printed in the paper itself" (§4, headline-number reachability).
  For Pingouin that was wrong: the printed-output examples the screening relied on live in
  the repo's **README** ("10 minutes to Pingouin": `pg.ttest(x, y)` → `T=-3.401, p=0.001,
  dof=58, cohen-d=0.878, power=0.917, BF10=26.155`, etc.), **not in the paper**. README
  examples are not the paper's claims: criterion 6 grounds every claim verbatim at a span
  in the paper text, and the paper has no such spans. Verifying README numbers would be
  verifying the README, not the paper — the anti-inflation guard exists precisely to
  refuse this.

### Failing criteria

- **4 (machine-readable headline numbers)** — the paper makes no quantitative claims at
  all; there is nothing to bind.
- **6 (claims rule fixed before binding)** — the rule "all numeric values printed in the
  paper's code-block outputs" is vacuous: the paper has no code blocks; there are no spans
  to find.

The environment build was not attempted: the claims-level blocker precedes any run, and
an env outcome could not change it (even a perfect 2018-era build leaves zero claims).
The JOSS review thread and HTML page were checked; both confirm the summary-only text.

### Consequence

- Pingouin is **not** a panel paper. No fixture, spec, record or tests will be committed
  for it. The panel is now: Perrin et al. (next up), tableone and Tensorpac (stretch);
  the pooled R1 number is computed over what actually banks (`spec.md:36-39`). The
  screening-level "all 7 met" for a paper that fails at the probe is exactly what §4's
  honest note ("verified only at the level of…") reserved for dev time.
