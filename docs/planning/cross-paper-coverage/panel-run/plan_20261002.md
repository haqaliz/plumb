# Plan — panel-run (cross-paper-coverage, aspect 2)

Date: 2026-10-02. Source: `docs/planning/cross-paper-coverage/prd.md` (approved) +
`docs/planning/cross-paper-coverage/panel-run/spec.md`. Execution: agents team for the
screening and per-paper work; the owner (delegated) makes the final panel call; strict
TDD where code is written; commits per unit on `feat/cross-paper-coverage/aliz`.

## The pipeline per paper (the AgroDesign template, `fixtures/gate/agrodesign/` +
`tools/gate_run.py` + `tools/agrodesign_spec.py` + `tests/gate/`)

1. **Select** (rule in spec; screening note first).
2. **Fixture** — fetch the paper PDF (dev-time network, `tools/fetch_pdf_fixtures.py`
   precedent), verify license + SHA-256, commit under `fixtures/gate/<slug>/` with the
   provenance README and `source.json`.
3. **Spec generator** — `tools/<slug>_spec.py`: read the paper, encode the claim rule as
   data tables, find spans via `unique_offset`, derive claims + bindings +
   unrepresentable + DRIVER together; `python -c <driver>` style entry point.
4. **Dev-time run** — `tools/gate_run.py` shape: `resolve_git` at the pinned rev (or
   archive), real `build_environment` (dev-time only), `run_and_capture` in a working
   copy, freeze env, write the record (trace, locatable objects, verdicts,
   environment.txt); M4a drift run only when a `DIVERGED` appears.
5. **Commit the record** + fixture tests: grounding/PDF-hash/rule-count
   (`test_<slug>_fixture.py`), byte-identical replay (`test_<slug>_replay.py`),
   no-local-path scan, recovery measurement (`test_<slug>_recovery.py` — floor only
   where it clears).
6. **Bank** — `plumb corpus bank fixtures/gate/<slug>/` (case lands in `corpus/local/`),
   labels transported only where owner-reviewed.
7. **Report** — `plumb corpus report` pooled over the panel (the `r1-report` aspect
   publishes the number + `docs/ROADMAP.md` update).

## Phase ordering

- **P0 — Selection rule + spec commit** (this plan + the spec; the rule precedes any
  selection). Commit: `docs(cross-paper-coverage): panel-run — fixed selection rule,
  aspect spec, plan`.
- **P1 — Screening note** — a search agent surveys candidates (arXiv + GitHub code
  links; ReScience already exhausted per `gate-paper/survey.md:23-38`) and records each
  against the seven rule criteria. Output: `docs/planning/cross-paper-coverage/panel-run/screening.md`
  + the proposed panel. Owner (delegated) confirms the panel.
- **P2 — Paper 1 end-to-end** (floor milestone): fixture → spec → run → record → tests →
  bank → pooled report shows ≥ 2 cases. Commit per sub-step, in the house
  test-first order: fixture tests before the spec generator, etc.
- **P3 — Papers 2–3** — each an independent committed unit (may run in parallel via the
  agents team; dev-time runs are serialized by the machine's CPU).
- **P4 — Recovery + panel verification** — per-paper recovery measured and reported;
  pooled report verified over the panel; hand the number to `r1-report`.

## Validation

- After each paper: `uv run pytest tests/gate tests/cli tests/corpus` + full suite;
  no network in tests (the autouse blocker); real env builds run only via `tools/` at
  dev time.
- The panel's pooled `corpus report --json` is byte-identical across invocations.

## Edge cases

- A candidate's repo fails to run at dev time → documented selection miss in the
  screening note; not forced through.
- `DIVERGED` → M4a drift run required; a verdict that changes → `UNVERIFIED`, never
  `DIVERGED` (`gate-paper/prd.md:92-96`); owner review recorded before labels.
- Recovery below floor → reported, not silently retuned; C1 changes are their own
  separate aspect if the owner asks for them.
- Stale/committed outputs in a repo → the freshness guard records them `STALE_ARTIFACT`,
  never read as fresh (constraint #5).

## Agent execution notes

  (`tools/gate_run.py` is the only networked script — new per-paper runners follow it).
- Checkpoint after P1 (panel chosen) and after P2 (floor milestone) for human review.
